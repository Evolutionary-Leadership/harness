### Fixes
- **Railway only:** a first setup could stall for six minutes waiting for
  environment URLs that were never going to arrive, then time out with
  advice pointing at causes that had not happened, while the one-time
  provisioning workflow stayed armed in your repository. Two workflows
  were racing to clean up the same file and one of them lost silently.
  Each now owns that file on exactly one path, and setup completes on the
  first attempt.
- **Railway only:** provisioning no longer reports success when its own
  cleanup failed. The cleanup push retries against a branch that moved
  under it, and a run that still cannot finish turns red with both
  environment URLs in its log, so the last step can be completed by hand
  in one commit instead of being discovered days later.
- **Railway only:** the secrets preflight no longer mistakes a busy branch
  for a permissions problem. A rejected result push is retried before the
  run concludes anything about your token.

### Improvements
- Setup asks for less of your attention and finishes sooner. The questions
  now arrive in a single round while branch and secrets preparation runs
  behind them, and on the standard foundation the verification runs while
  Railway provisions rather than before it. Every wait between steps also
  backs off progressively instead of sleeping a fixed interval.
- When setup does time out, it tells apart a provisioning failure from a
  provisioning run that succeeded and only failed to publish its result,
  and it names the recovery for the second case, which is the one you are
  most likely to hit.
- The deterministic half of setup (the checks, the waits, the file copies,
  the single configuration commit, the watch for your URLs) now runs from
  a script instead of being narrated a step at a time, so it behaves the
  same way in every repository. It deletes itself along with the setup
  skill when setup finishes.
- An upgrade will never reinstall setup machinery into a project that is
  already configured, so a repository past setup stays clean.

### Notes
- Nearly all of this lands at setup time. A project already past setup
  receives the workflow fixes through the upgrade, keeps its existing
  environments and URLs, and has nothing to change.
- Setup is still a single session that ends with your live URLs printed.
  The questions it asks, and their wording, are unchanged.
