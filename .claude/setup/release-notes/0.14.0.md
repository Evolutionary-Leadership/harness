### Breaking
- `.claude/scripts/board.sh` is gone, replaced by `.claude/scripts/cockpit.sh`.
  Its `post` and `read` commands keep exactly the surface the old client had
  (same flags, markers, stdin body and exit codes), so anything of your own
  that calls it only needs the new path. `/harness-upgrade` proposes the new
  client and the old one's deletion together; if you call the old path from a
  script the harness does not manage, update it before upgrading.
- **`/harness-upgrade` now stops and asks** when your `check:` line runs
  `check:spec` while `.harness-version` carries no `spec_product:` key. That
  combination means your anchor gate has been a no-op since v0.10.0: it
  stopped enforcing and your build stayed green. **Fix it now rather than
  waiting for an upgrade:** add `spec_product: <slug>` naming the Spec
  Universe product your specification lives under, or drop `check:spec` from
  the `check:` line if you meant the gate to be dormant. The upgrade applies
  nothing until the question is answered.

### Features
- `/setup` now asks for your System Registry change prefix and verifies it
  where credentials exist, writing `change-prefix:` and `system-key:` for
  you. Since v0.12.0 `/feature` has required that key, but nothing asked for
  it, so every new scaffold hit the wall at its first feature with no way
  past but an unverified hand-typed prefix. The hand-off now always names
  which of the three prefix states your repository is in, and the exact line
  to add when there is none.
- `/feature` phase 0 verifies the prefix at Capture, before minting a key. It
  refuses only on an answer: the prefix resolves to nothing, or to a system
  other than the one recorded. A registry outage never stops a Capture.
- `.claude/scripts/registry.sh` ships as a read-only System Registry client
  beside the cockpit client, reading `REGISTRY_URL` and `REGISTRY_TOKEN` and
  nothing else.
- The cockpit client gains `ping`: a scope hint POSTed to the cockpit's
  refresh endpoint when a work item is created, when the first touched-set
  record is written, and after every phase write. A configured cockpit learns
  where to look within a second instead of at its next poll. The hint carries
  a repository, a change key and a source list and nothing more: an address,
  never a fact, never a position, never a session identity.
- The cockpit client also gains `report`: one sentence about what is
  happening inside the position a change sits at. A record says where a
  change is; a report says somebody is still there and what they are doing.
  Sessions report at eight seams (a phase boundary, a question round asked
  and answered, a gate put and its verdict, a long operation starting and
  finishing, a stand-down), all of them inside procedures your skills already
  quote, so nothing you add later has to remember to report.
- Every scaffold now ships `.claude/journey-bindings.json` beside
  `.claude/JOURNEY.md`: one entry per journey position naming the cockpit
  rule expression that observes it and its recency window in seconds. If you
  run a cockpit, its operator stops retyping up to 23 bindings per product,
  and an upgrade can be diffed against the file.

### Fixes
- A cockpit call that fails now says which command failed, so a failed `read`
  no longer claims an ask was not posted.
- A 4xx that is not a credential problem reads as a refusal naming its
  status, rather than as an outage. The fix for a refusal is in your own
  configuration, and calling it unreachable sent you to the wrong place.
- `COCKPIT_SOFT_TIMEOUT` (default 5 seconds) governs both `ping` and
  `report`, so a phase write never waits out the longer timeout the posting
  commands use.

### Notes
- **Neither `ping` nor `report` can stop a session.** Both exit 0 on every
  runtime path, print nothing at all when no cockpit is configured, and print
  nothing on success. The single loud case is a usage error in the calling
  recipe, which includes naming a journey position that does not exist.
- **A report never moves a change.** The position a report names is stored as
  the producer's own words, and placement never consults it.
- The binding manifest declares nothing instance-specific: every join value
  is a placeholder pattern, so the shipped file is byte-identical in every
  scaffold at a version. It carries the harness version it shipped as, so a
  cockpit meeting a vocabulary it does not know can name the mismatch instead
  of quietly placing nothing.
