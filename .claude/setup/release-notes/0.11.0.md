### Features
- When two features run at once in one repository, each now **declares what it is going to touch before it touches it**, so the second one sees the overlap while there is still time to do something about it rather than at the merge. `/feature` phase 0 writes the declaration onto the `coordination` branch, the feature-context beat refreshes it, and phase 5 refreshes it again.
- The declaration always carries **paths**. Where your project has connected a specification, it also carries the specification nodes the change intends to touch, and a change that touches none says `spec: none` rather than staying silent, so an empty declaration is never confused with an unwritten one.
- Three new readers on `.claude/scripts/coordination.sh`: `features` lists every in-flight declaration, `feature <slug>` shows one, and `feature-branches` lists the branches behind them. You read the result at phase 0 and at phase 5.

### Notes
- **This is advisory and it is never a gate.** Nothing here returns a failing exit code or blocks a merge, by design: the collision worth catching is one between two branches that have not merged yet, which no merge gate could see. What it gives you is a person reading a short report at two moments where a redirect is still cheap.
- **A record is deleted by the feature that wrote it, at its merge**, and any record left behind is swept by the next reader once its branch is gone from the remote. There is no cleaning schedule and no workflow, so nothing new runs on a timer in your repository.
- **An unreachable `coordination` branch warns and continues.** Every read exits quietly and every write warns in one line. That is deliberately the opposite of the specification gate, which stops the build when it cannot read: a declaration nobody could write is an inconvenience, and a specification nobody could read is an unverified build that looks verified.
- Files are named by **feature slug**, not by change key, so the namespace is writable in a project that has not connected a specification and therefore has no key to mint. Where you do have one, your slug already begins with it and the record carries the key as a field.
- A malformed record is named and skipped when read, never fatal. There is deliberately no check for it: this branch never reaches CI, so a checker could not run. What is tested instead is the writer.
- Declare the work, not the bookkeeping. The harness's own session files are touched by every feature there has ever been, so declaring them would put a collision in every report, which is how a report stops being read.
