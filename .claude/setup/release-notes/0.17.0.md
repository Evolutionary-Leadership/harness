### Breaking
- `/feature --ship <prompt>` now runs from the first prompt to a tagged release on `main`. It no longer needs `agent-authority: release` and no longer stops at `preprod` without it. A repository that wants a human on every diff runs without the flag. `agent-authority:` still decides the exit for an unattended run that carries no flag, and still gates `/hotfix` and `/rollback`.
- `/feature` sizes every change at the end of Capture (S, M or L, against a written rubric in the skill) and runs fewer phases for S and M: S is Capture, one plan-and-go gate, build, ship; M adds one grill and one plan gate that shows spec and tickets together. `--quick` now means "force S". For S and M the spec lives in the work item's `## Specification` section and the tickets are a checklist in `## Tickets`, not sub-issues; anything that read sub-issues (a board filter, a cockpit frontier query) now reads issues for L only.
- Every skill except `/endchat` can now be invoked by the model. The skills that reach production are gated by their `## Authority` section, as before; the frontmatter flag was never the gate.
- `claude-to-preprod.yml` is two jobs, `gate` and `merge`; anything that watched the `to-preprod` job by name watches those two. The `preprod-write` lock is held only by `merge`.
- `release.yml` merges `preprod` straight onto `main` and opens a pull request only when that push is refused by branch protection.
- `.harness-feature` may carry a second line, `preview: yes` or `preview: no`. `.harness-version` gains `tests:` (a test command CI runs in its own job with a Postgres service) and `registry: off` (skip the System Registry prefix check at Capture). The recommended `check:` line no longer starts with `pnpm install --frozen-lockfile &&`: the workflow installs before it runs.

### Features
- One Bash call writes a journey position, inside the claude.ai sandbox and out of it: `bash .claude/scripts/journey.sh phase <position> "<sentence>"` commits the record to `.harness/journey/<slug>.md` and pushes the session branch, and a new `journey-sync.yml` workflow mirrors it onto the coordination branch and rings the cockpit. The position reaches the cockpit 20 to 40 seconds later.
- A `tests:` line in `.harness-version` runs in CI, in a `tests` job beside `check`, with `TEST_DATABASE_URL` pointing at a Postgres service. The merge gate waits for both.
- `node scripts/check-docs.mjs --diff <ref>` names the architecture docs whose `sources:` match the diff, the surface counts that changed and the doc paths newly referenced, or `nothing`. `/feature` phase 4 and `/to-preprod` run the docs agent only when it prints something, with that output as the agent's whole scope.
- `.harness-version` accepts `registry: off`, so a project whose prefix is deliberately unregistered no longer needs a CLAUDE.md guardrail overriding a harness-managed skill.
- **Railway only:** previews are opt-in. `set-feature-name.sh <slug> --preview=yes` (or the `/review` exit) provisions one; S and M changes going straight to `/to-preprod` do not fork an environment they never open.

### Fixes
- A `/feature --ship` run of a one-file change no longer takes 20 minutes. The session spent that time on about 150 bookkeeping tool calls and on re-sending 50 to 60k tokens of procedure on every one of them, not on the code. Journey writes are one call, cockpit reporting costs nothing where no cockpit is configured, `/feature` loads a third of the text it did and `/to-preprod` and `/code-review` between half and two thirds (the `--ship` and connected-mode procedure moved to `SHIP.md` and `CONNECTED.md`, read only when they apply), and the `/feature` invocation is quoted once instead of six times.
- A preprod merge ran the same check three times (on the `claude/` push, on the pull request opening, and again after the signal-file strip). The merge path now runs it once: `/to-preprod` pushes once, and the workflow strips before the pull request opens.
- Two features merging in the same hour queued on each other's CI. The lock is now held only around the write.
- `/release` chained after `/to-preprod` waited a full minute of stillness on `preprod` in every repository; it now waits only where a changelog accumulator workflow exists, and only for that commit. The drafted release note is shipped when it validates instead of being rewritten bullet by bullet.
- **Railway only:** the post-push hook slept up to 80 seconds on every push until a preview URL existed, and phase 5 blocked the session for up to 8 minutes verifying a preview that `/to-preprod` then deleted, while no `preprod` deploy was ever verified. The hook fetches once and never sleeps, and no session waits on a deploy: a new `verify-deploy.yml` checks every preview after it is provisioned, `preprod` after every merge and production after every release, and sets a `deploy/preview`, `deploy/preprod` or `deploy/production` commit status.
- A fresh remote session that could name nobody had its first commit refused by every skill that commits, with only `set-feature-name.sh` carrying a per-command fallback. The session start now sets a repo-local identity (never a global one) when `git config user.email` is empty, and leaves an existing identity alone.
- A cockpit that refused every report with 404 said only "404". It now prints the cockpit's own sentence (which product is missing), and the session start pings once so a misconfigured product is found before any work.

### Improvements
- `/release` proposes the version bump from the blast radius: subjects marked breaking, removals and retirements, or a `DROP COLUMN` in a new migration propose a minor (pre-1.0) or major bump with the lines quoted. It tries a plain `git push` before falling back to the MCP push, and says which path it took.
- Connected mode judges only what changed: `judge-plan.mjs prepare` builds the four inputs in one command, `plan --diff-base` drops nodes reached only through files whose hunks touch no anchored block, judges write their tables to disk so a review can resume, a tier-1 drifted row is never acted on before tier 2, a drifted row in a file the branch never touched is a `known-stale-baseline` rather than new drift, and claims post in one batched call.
- The em-dash hook scans a Bash command only when it carries a heredoc or a message flag, and also guards the MCP issue and pull-request writes. A `Frozen: Yes` record in `docs/README.md` refuses an edit that does not append.
- The retry envelope is 10 minutes and 5 retries instead of 15 and 15.
- **Railway only:** the recommended `check:` line for a Railway scaffold includes `pnpm build`, which catches the class of failure the deploy verification used to catch, without a deploy.
- Capture builds a `## Brief` in the feature context with `brief.sh`: the CLAUDE.md guardrails, glossary terms, decision records and architecture docs that the change's title, why and declared paths reach. Later phases, `/to-spec`, `/to-tickets` and the Standards reviewer read it first and open the full docs only where it names them.
- `.claude/HARNESS.md` is under 500 lines: its managed-files table is now `.claude/harness-manifest.json` (every shipped path with its upgrade class and variant). The session-start hook still sends every session through `getting-started` first, which holds the closing block, the stand-down block and the rule that skills are mandatory.
- `/to-tickets` creates an L change's tickets, sub-issue links and blocking edges from one Bash call, using the ids each create returns, instead of one tracker round trip per ticket.
- `check-docs.mjs` treats a surface-count mismatch as an error on a pull request run or under `--strict`, and as a warning on a `claude/**` push. The docs-updater's rule is now that a changed surface and its owning doc land in the same pull request, not the same commit.
- `scripts/strip-em-dash.sh` replaces em dashes in generated text (issue bodies, ticket lists, release notes) before it is written, so the hook never has to block it.
- `/setup` writes `tests: pnpm test:unit` beside `check:` for a foundation scaffold, and `registry: off` when answered "no registry" (`--registry off`).

### Notes
- Foundation projects: the vitest `projects` split (`unit` and `integration`), the one-container test database with a template database per file, the fast-fail `verify` order and `scripts/test-db.sh` reach new scaffolds only. To adopt them, copy `vitest.config.ts`, `tests/integration/helpers/global-setup.ts` and the `package.json` scripts block from a fresh scaffold, add `tests: pnpm test:unit` to `.harness-version`, and supersede the decision record that says CI runs no tests.
- If you use the Product Cockpit, add `BOARD_URL` (a variable or a secret) and `BOARD_TOKEN` (a secret) to the repository's Actions settings: the journey workflow rings the cockpit from there now, not from the session. Keep them in the session environment too: the session still sends its gate and round reports, and writes in-progress positions only where it sees a cockpit.
- `/harness-upgrade` does not carry an existing project across this release automatically. Add the `tests:` line, drop the leading install from `check:`, replace a registry guardrail in CLAUDE.md with `registry: off`, and re-read `.claude/HARNESS.md` for the new `.harness-version` keys.
- `.claude/settings.json` is a config file that `/harness-upgrade` merges by key only, so the new hook entries and the retry envelope do not arrive on their own. Copy them in by hand from a fresh scaffold or the template: `protect-frozen-docs.sh` on `Write` and `Edit`, the em-dash hook on the seven `mcp__github__` write tools (`create_or_update_file`, `push_files`, `issue_write`, `add_issue_comment`, `update_issue_comment`, `create_pull_request`, `update_pull_request`), and `API_TIMEOUT_MS` at `600000` with `CLAUDE_CODE_MAX_RETRIES` at `5`.
- The rule that a decision about production must be made by a person is unchanged in spirit: `--ship` is that decision, typed by a person about this session, and every release still produces its blast-radius report.
