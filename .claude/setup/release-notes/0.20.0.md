### Fixes
- `/feature --ship` in auto mode now reaches a tagged release on `main` without a person. The Claude Code permission layer never sees the `--ship` flag, so it refused the release push to `preprod` at `/release` step 9; `.claude/settings.json` now pre-approves exactly that push and its dry run, and nothing broader. Your repository gets the two `permissions.allow` rules and the `release-push-gate.sh` hook on its next `/harness-upgrade`, which adds them beside your own entries and changes none of yours.

### Improvements
- `/release` checks its authority with `.claude/scripts/release-authority.sh` before anything else and again before the push, so a session without your `agent-authority: release` grant, a `--ship` run, or you asking in the turn is refused by the harness itself. Under `--ship` the evidence is the `Invoked with: --ship` line `/feature` writes into the feature context; `/continue` rewrites it, so a flag typed yesterday never releases today.
- The `release-push-gate.sh` hook blocks any push the new rules would match that is not the exact release push, and pre-approves the GitHub API route only for the release commit to your own `preprod`. `/hotfix` and `/rollback` are unchanged: nothing pre-approves a push to `main`.
- When the permission layer refuses the release push anyway, `/release` stands down with `authority-not-granted` and names the rule to add, or asks for a person to type `/release`, instead of trying another route.
