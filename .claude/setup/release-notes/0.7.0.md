### Breaking
- The gate branch is now `preprod`, and nothing renames your project for
  you. Rename the branch formerly called `dev` to `preprod`, make it the
  default branch, and the flow works again. Until you do, a session push
  still reaches your feature branch but no pull request opens, because the
  merge workflow targets a branch that does not exist yet.
- `/mergedev` is now `/to-preprod`. The old name is gone rather than
  aliased, so a session that reaches for it will simply not find it.
- **Railway only:** rename the persistent non-production environment to
  `preprod` and point its deployment trigger at the `preprod` branch.
  Feature environments are forked from it by name, so previews keep
  failing until both match.
- **Railway only:** on a fresh scaffold the bootstrap cleanup commit now
  publishes `preprod-url:` in place of the old key. A project already past
  setup has nothing to change.
- An upgrade cannot do any of the above. It updates files, never branches
  or hosting, so plan the rename as a short maintenance window rather than
  something an upgrade will absorb.

### Improvements
- The branch is now named for what it does. `preprod` is the gate between
  your feature branches and production: work merges there and waits, and a
  release promotes the whole queue to `main`.
- `/to-preprod` sits beside `/to-spec` and `/to-tickets`, so the commands
  that move work forward finally read as one family.
- A feature branch can no longer be named after the gate. The name guards
  reject `preprod`, and they still reject the retired name, so neither can
  be minted by muscle memory.
- The bootstrap workflow guarantees `main`, `preprod` and `coordination`,
  and the branch descriptions it writes explain the gate to whoever opens
  them.

### Notes
- Each stage is now named for where the work actually happens: development
  in the session, testing on the feature branch and its environment,
  `preprod` as the gate, `main` as production.
- Names that were considered and rejected, for anyone tempted to rename
  again: `staging` describes a deploy target rather than a gate; `next`
  collides with Next.js in every search across a scaffolded project; and
  `integration` and `acceptance` each collide with a test tier this
  harness already defines.
- This repository is generated. Edits made here are overwritten on the
  next update, so scaffold from it with "Use this template" rather than
  editing it in place.
