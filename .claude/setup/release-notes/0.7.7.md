### Improvements
- The release procedure your `/release` skill describes is clearer about where
  a version number comes from and who writes it, so a release cannot end up
  with the version, the changelog entry and the tag disagreeing.
- `release.yml` gained a version-stamping step that is inert in a project that
  consumes the harness rather than publishing it. It is guarded on files only
  the authoring repository has, so it does nothing in your project's releases.

### Notes
- An upgrade is optional. Nothing in this release changes what a scaffolded
  project does at build, deploy or release time; the parts that moved are the
  ones the authoring repository uses to publish this template.
