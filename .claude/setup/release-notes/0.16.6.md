### Fixes
- **Railway only:** a merge to preprod could stall forever, reporting a CI failure that had not happened. A preview-provisioning run that was still in flight when `/to-preprod` started would publish `.railway-url` on top of the merge commit, and that commit became the pull request head. GitHub does not run `pull_request` workflows for a push made with the Actions bot token, so the merge gate polled a head that could never turn green and timed out after twelve minutes. Provisioning now checks whether its environment is still there before publishing, and stands down when a merge is tearing it down. A preview opened by `/review` keeps its URL as before.
- The merge gate now recovers a pull request head that cannot produce a check run, instead of waiting out its budget. It re-strips the signal files under your `PAT_TOKEN`, which starts a real check run on a real head, and it does this at most twice before giving up. The gate still merges only on a green check it actually observed, so this makes an unattended run finish without making CI decorative.
- A gate that gives up now says the head was pushed with a bot token and cannot produce a check, and that CI never ran. It used to report that CI status was pending, which sent you looking for a broken test that did not exist.
- **Railway only:** Railway refuses to create an environment whose name is too long, answering only `Error in name - Invalid input`. Provisioning now reports that refusal with the name and its length, rather than polling for sixty seconds and then saying the environment was not created.

### Improvements
- `/feature` phase 0 now tells you which exit an unattended `--ship` run will take, before it builds anything. Where `.harness-version` does not carry `agent-authority: release`, it says plainly that the run will stop at preprod without reaching production, and names that line as the one thing that would change it. You no longer find this out at phase 5 with the work already built.
- Where the grant is present, a `--ship` run now runs all the way to a tagged release without stopping. `/release` used to ask one confirmation about the release's blast radius, which an unattended run had nobody to ask. The grant is the consent and the flag says nobody is watching, so the question is skipped and the blast-radius report is still produced and recorded. A run without the grant is unaffected: a flag is still never authority to reach production.
- Feature name slugs are now capped at 27 characters instead of 40. Railway refuses to create an environment named much above that, and `/feature` spends roughly eight characters on the change-key prefix before your description starts. A longer name you pass to `set-feature-name.sh` is truncated with a note saying so. Branch names already in flight are unaffected: the workflows still resolve the longer shape, so a feature named under the old cap keeps its branch.
