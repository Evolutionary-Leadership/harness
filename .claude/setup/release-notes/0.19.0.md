### Features
- `/release` now closes the work item of every change it ships, in every project, not only one that connected a specification. After pushing the release it waits until `main` carries it (on Railway, until `verify-deploy.sh` confirms production serves it), then closes each `<KEY>: ...` work item with a comment naming the version. A release that production does not yet serve closes nothing, and re-running step 10b later finishes the job. Your open work items finally mean unshipped work; ones you closed by hand before stay as they are.
- `/to-preprod` and `/review` now name the change key and work item under `## Spec` in every PR body, and `/review` adds the `Why:` line `/to-preprod` already wrote. That is how `/release` finds what to close; for pull requests merged before this version it falls back to the `Why:` line, then a `<KEY>:` prefix on the title, and lists any it cannot match rather than guessing.

### Fixes
- `hotfix.yml` pasted the hotfix's PR title and version (free text from `.pr-description.md`) and the branch name straight into its shell scripts. A title with a double quote broke the hotfix, and one containing `$(...)` or a backtick ran as a command in a job holding your `PAT_TOKEN`. Every value now reaches the script through the step's `env:` block, so it is always plain data.

### Improvements
- The template's README is rewritten for someone arriving for the first time: three steps, what `/setup` will ask, the one answer that is final (the MCP layer), and the change-prefix line a first `/feature` needs, with its `registry: off` alternative.
- **Railway only:** the production check `/release` runs moved from `release/CONNECTED.md` into `release/LANDING.md`; an upgrade replaces the Railway copy of `CONNECTED.md` with the shared one. Nothing to do on your side.
