### Features
- A stray `feature/<name>` branch can now be removed from a session, which cannot delete branches itself. Dispatch the new `feature-branch-remove.yml` workflow with the branch name. It refuses a branch that has an open pull request or is still declared on `coordination`, and on Railway, deleting the branch also tears down its preview environment. `/endchat` and `/to-preprod` point at it.
- `coordination.sh adr-collisions` reports any decision record on your branch whose number is already taken on `preprod`, on another feature branch, or by another feature's claim. `/feature` runs it with its overlap check, and `/to-preprod` runs it before the merge, with the steps for renumbering.
- **Railway only:** a feature branch can set variables on its own preview environment. Commit `.harness/env/<name>.env` with `KEY=value` lines, where `<name>` is the feature name, and the next provisioning run sets them on that preview's app service and nowhere else. Values must be literals and never secrets, because the file is committed. Keys the harness or Railway own (`DATABASE_URL`, `PORT`, `BETTER_AUTH_SECRET`, `AWS_*`, `RAILWAY_*`) and reference values are refused, and no value is ever printed. The file is stripped when the feature merges.

### Fixes
- A pull request that failed to merge could leave a second, stray `feature/<codename>` branch (and, on Railway, a second preview environment) once the documented recovery ran. Conflicts in the signal files now resolve to the session's side automatically, and a push that has lost the feature name its branch set is refused with the one command that restores it (`set-feature-name.sh --no-push <name>`), instead of opening a branch under the session's codename.
- The recovery in `/to-preprod` step 8 did not re-trigger the merge: a re-push that left `.pr-description.md` unchanged never reached the pull request. The step now says a recovery push must change that file, committed as `chore: trigger auto-merge to preprod`, and that a conflicting pull request is recovered by merging `origin/preprod`, never the feature branch. The workflow's own failure comments point at the same recovery.
- A pull request that conflicts with `preprod` is now reported as a conflict, and a merge that did not complete now fails the to-preprod run. The first used to surface as a bot-token problem, and the second as a green run that had merged nothing.
- After a feature was named, Claude Code on the web refused every later commit in the session, because `set-feature-name.sh` wrote a bot identity into `.git/config`. It now commits as the session and writes no identity.
- A `.pr-description.md` title written in quotes kept its quotes in the pull request title. One surrounding pair is now stripped, and `/hotfix` titles are read the same way; write titles unquoted.

### Improvements
- When the cockpit refuses your repository's activity reports, the session now says so once, prominently, with the cause and the fix, and `/feature` sends its first report at phase 0, so you see it before any work starts. A 404 on every report means no cockpit product is linked to your repository, which is changed in the cockpit, not in the repository.
- Every path that writes a decision record now claims its number first, so two features in flight no longer pick the same one unnoticed.
- `/feature` documents how to continue a change after its merge: start from `origin/preprod` and name a new feature under the same change key.
