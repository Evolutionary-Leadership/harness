### Breaking
- **`/to-preprod` and `/review` can now be run by Claude itself.** Both lost
  the frontmatter flag that kept them out of the model's reach, because
  neither reaches production: one merges to `preprod` through an auto-merged
  PR, the other opens a PR and merges nothing. If you relied on the flag to
  stop a session merging its own work, that is no longer what stops it; the
  skills' own preconditions are. Nothing changes for you when you type the
  commands yourself.
- **`/release`, `/hotfix` and `/rollback` now refuse to start without
  authority.** Each opens with an `## Authority` section and checks it before
  any other step. A session that has neither a grant nor your ask in the same
  turn stops there and says so, rather than doing the work and stalling at the
  push. Typing the command yourself is one of the two things that satisfies
  it, so an interactive session is unaffected.

### Features
- **`agent-authority:` in `.harness-version`** grants Claude the right to
  finish a production-reaching skill with nobody watching. It takes a space or
  comma separated list, and absent or empty grants nothing, which is the
  default:

      agent-authority: release

  Only `release`, `hotfix` and `rollback` mean anything in that list. Add it
  when you want unattended sessions to be able to ship; leave it out and they
  will build, merge to `preprod`, and hand the release to you. The key is
  yours, not the harness's: an upgrade never rewrites it.
- **A blocked session now says so in one fixed shape.** When Claude cannot
  finish something, it emits a stand-down block with five keys (what is
  blocked, why, what was finished, what was not, and what would unblock it)
  and a closed vocabulary of three reasons. If you run several sessions and
  read their output in bulk, you can match on it.

### Fixes
- **A session can no longer report work as complete while it sits unmerged.**
  This is the fix that matters most in this release. Before it, a session that
  reached its exit and could not take it had no prescribed way to say so, and
  some of them said "done" instead. A reply carrying the stand-down block is
  now forbidden from claiming completion, and `/feature` says the same thing
  where it stands down.
- **An unattended session can reach the end of its own work.** Previously it
  would stop at `/to-preprod` asking a person to run the step for it, which
  for an unwatched session meant waiting forever. It now files its own work
  and only stands down at an exit it genuinely may not take.
- **`/feature` tells you at phase 0 which exits this session can reach**,
  instead of discovering at phase 5 that it cannot file what it just built.

### Notes
- **Performing a gated skill's steps by hand is treated as the same act.**
  Reading `/release`'s `SKILL.md` and following it is a legitimate route and
  stays open, but without authority it is refused in the same words as
  invoking the skill. A guard that only stopped the literal command would not
  be a guard.
- **Deleting a remote branch is human work**, and `.claude/HARNESS.md` now
  says so under "What a session can finish alone". The harness git proxy
  accepts pushes only to a session's own `claude/` ref, so a leftover
  `feature/<name>` branch after a release needs a person or the GitHub UI. The
  `claude/` branch itself is already deleted for you by the release workflow.
- `.claude/HARNESS.md` gains a "What a session can finish alone" section
  listing every skill against that one axis. It is the place to look when you
  want to know what an unattended session will and will not do in your
  repository.
