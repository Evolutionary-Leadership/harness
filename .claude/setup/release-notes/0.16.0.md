### Breaking
- The journey binding manifest now names `release_workflow_activity` as the
  rule expression for the `releasing` position, replacing the Railway
  deployment signal. A cockpit that reads the manifest has to spell that
  expression in its own rule registry; until it does, `releasing` reads as a
  broken binding on every product it tracks.

### Features
- `releasing` is now observable on a project with no Railway connection. It
  was bound to Railway deployment activity, so a project that does not deploy
  to Railway could never be placed at that position at all. It now watches a
  run of the release workflow, which every project has.

### Notes
- The binding is still an activity signal with a one hour window. A release
  that goes quiet for longer than an hour reads as not releasing, and the
  position falls back to the last thing actually observed, which is the merge.
  That is the intended reading of a release run that is stuck.
- Railway deployment activity is still the richer signal where Railway exists,
  and a later release may restore it for Railway projects through the overlay.
  Nothing to do now, and no project needs to choose between the two.
