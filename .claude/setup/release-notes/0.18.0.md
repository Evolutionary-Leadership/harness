### Fixes
- A project that keeps its decision records in `docs/adr/` was offered ADR number 0001 by `/document`, with no warning, and the claim of 0001 then succeeded. `coordination.sh` now reads `docs/decisions/` and `docs/adr/` alike, for the next number and for the collision check, and says on stderr when `preprod` reads fine but holds no record, the one case where 0001 is right.
- `/release` told a project whose own `release.yml` already stamps `## [Unreleased]` to compose and push a second, competing changelog. It now skips the changelog when either the accumulator or your own workflow step stamps it, decides by reading that step's `if:`, and says in one line that it skipped and why.
- `/document` asked for permission on every ADR claim in the sandbox, because the GitHub tool its claim step hands off to was not pre-approved. It is now.
- `/hotfix` wrote a `hotfix: true` key that no workflow reads; the `hotfix/**` branch is what starts the hotfix flow. The key is gone from the skill and from `.claude/HARNESS.md`.

### Improvements
- `/feature` now says what to do when an overlap it reported has already merged into `preprod`: merge `origin/preprod` in and resolve the conflicts, never copy the other change in by hand. A one-parent commit titled "Merge" reads as merged and leaves the pull request conflicted.
- The template README's first steps say to grant the Claude GitHub App, and Railway's app on a Railway project, access to the new repository before `/setup`. An app installed for selected repositories only never sees a repository created from the template.
- **Railway only:** two comments in `feature-branch-railway.yml` said a checker enforces the merge-signal prefixes and the generate-then-mask pairing. That checker runs only where the harness is authored, so the comments now say the pairing is yours to keep when you edit either side.
