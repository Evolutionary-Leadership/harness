### Notes

- The release workflow gained one step, which stamps a repository's own
  installed harness version when it cuts a release. It is guarded so that it
  runs only in a repository that publishes a harness of its own, and a project
  scaffolded from this template publishes none, so the step never fires and
  your releases behave exactly as they did before. The workflow file is
  harness-managed, so an upgrade brings the new copy in; nothing else about it
  changed, and there is nothing to do.
